# Campus Code Lab - System Study Report

## Overview
Campus Code Lab is a Django-based coding platform designed for offline-friendly use in environments with limited infrastructure. It focuses on low-bandwidth and offline support using browser-based auto-save and execution on a local campus server via Docker.

## Current System Architecture

### Backend (Django)
- **Apps**: `users`, `assignments`, `submissions`.
- **Authentication**: Custom user model with `is_student` and `is_lecturer` roles.
- **Data Model**:
    - `Assignment`: Defines tasks with sample inputs and expected outputs.
    - `Submission`: Stores student code, execution output, and pass/fail status.

### Execution Engine (Docker)
- Uses a `TemporaryDirectory` to store code and input.
- Runs `docker run --rm --memory=64m --cpus=0.5 --network none python:3.10-alpine` to execute student code securely.
- Enforces a 2-second timeout via `timeout` command and `subprocess.run`.

### Frontend
- **Tech**: HTML, Tailwind CSS, Vanilla JS.
- **Offline Features**: 
    - Auto-saves code to IndexedDB every 3 seconds.
    - Queues submissions in IndexedDB when offline.
    - Automatically syncs pending submissions when connection is restored.

## Identified Issues & Bugs

### 1. Robustness of execution
- **Image Dependency**: The system assumes `python:3.10-alpine` is pre-pulled. If not, the first execution might fail due to the 2-second timeout while pulling the image.
- **Error Handling**: `stderr` is appended to `stdout` in the report, which might make simple string comparison for "PASSED" status fail even if the logic is correct but has a warning or unexpected stderr.

### 2. Validation Logic
- **Basic Comparison**: Current validation `str(output).strip() == str(assignment.expected_output).strip()` is very sensitive to minor formatting differences.
- **System Errors**: Identifying system errors by checking if output starts with "Error:" or "System Error:" is brittle.

### 3. Frontend UX
- **Run Feedback**: While offline, the "Run" button simply shows a "Cannot run tests while offline" message without much detail.
- **Sync Logic**: `syncPendingSubmissions` could be more robust in handling partial failures or large numbers of submissions.

## Proposed Improvements (Short Term)
1.  **Refine Output Validation**: Implement a more flexible comparison (e.g., ignoring trailing spaces on each line).
2.  **Improve Error Reporting**: Distinguish between user code errors and system errors more clearly in the UI.
3.  **Pre-pull Docker Images**: Ensure necessary images are available during system startup.
